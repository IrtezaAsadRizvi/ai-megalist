# v0: prompt-to-React UI for the Next.js stack

v0 sits in the design and app builder space alongside [Magic Patterns](magic_patterns.md), [Lovable](lovable.md), and [Bolt.new](bolt_new.md), but specifically as the polished component generator for React + Tailwind + shadcn/ui teams. v0 is what I use when I already have a Next.js codebase and I want a beautiful component, fast. It's the only "prompt to UI" tool that produces output I'd actually paste into production without a heavy rewrite, and that's because Vercel built it specifically for the React + Tailwind + shadcn/ui stack everyone in their ecosystem already runs.

## What it actually is

Vercel's UI generator. You describe a component (or a full page); v0 produces React + Tailwind + shadcn/ui code, with a live preview. Newer versions can scaffold full Next.js applications, but the sweet spot is still "give me one polished component."

## Setup

1. Go to [v0.dev](https://v0.dev), sign in with Vercel/GitHub.
2. Free tier gives ~10 credits/day; Premium is $20/mo for 200 credits.
3. Type a prompt: "A pricing table with three tiers, monthly/yearly toggle, dark mode, accessible."
4. v0 generates 2 to 4 candidates. Pick one, refine in chat ("Make the middle tier featured," "Add a free trial CTA").
5. Copy the code, or use the "Open in v0" CLI: `npx v0@latest add <component-id>`.

## How I use it day to day

* **Marketing pages.** Hero, features, pricing, FAQ - v0 nails the genre on the first try ~70% of the time.
* **Forms.** "A multi step checkout form with validation." The shadcn/ui foundation means form components come with accessibility built in.
* **Dashboards.** Tables, charts, sidebars. Less polished than full app builders but enough for a competent first pass.
* **Iterating in chat.** Describe a tweak, v0 regenerates only what's needed. The diff is visible.
* **Refining locally.** I copy the code into Cursor, then make Cursor pretty up the rest of the app to match the style.

## Gotchas

* v0 assumes Next.js, Tailwind, and shadcn/ui. If your stack is different (Vue, Svelte, plain CSS), the generated code is less useful. There is some cross stack support but it lags.
* The credit system is generous on Pro and miserly on free. Don't evaluate seriously on the free tier.
* Generated code occasionally references components that don't exist in your shadcn install. Run `npx shadcn-ui@latest add <component>` to fill the gaps.
* No real backend logic. v0 is UI only; pair with Lovable, Bolt, or your own backend.
* Multi page generation (full app mode) is impressive but the output is harder to maintain than the single component flow. Prefer one component at a time.

## Alternatives

* If you want full-stack from prompt with hosting and a backend, [Lovable](lovable.md) or [Bolt.new](bolt_new.md) cover the broader scope.
* If you want React plus Figma output in one tool, [Magic Patterns](magic_patterns.md) is the closest comparator.
* If you want prompt-to-design (not code), [Google Stitch](google_stitch.md) and [Uizard](uizard.md) are design-first.
* If you want a full design system in your IDE while you code, pair v0 with [Cursor](cursor.md) for the refinement loop.

## FAQ

### Is v0 free?

Yes for ~10 credits/day, which goes fast. Premium is $20/mo for 200 credits and is the realistic floor for daily use. Don't evaluate seriously on the free tier.

### v0 vs Lovable - which should I use?

Different scopes. v0 generates one polished component or page at a time, copy-paste into your existing codebase. [Lovable](lovable.md) builds full-stack apps with hosting and Supabase. Use v0 for refining UI in a real project; Lovable to scaffold the whole thing.

### Does v0 only work with Next.js?

It's tuned for React + Tailwind + shadcn/ui. Other React stacks work; Vue, Svelte, and plain CSS get less useful output. If you're not on the Vercel-blessed stack, [Magic Patterns](magic_patterns.md) is more agnostic.

### Can v0 generate full apps?

There's a multi-page mode that scaffolds a Next.js app. The output is harder to maintain than single-component generations - I prefer one component at a time and assemble in [Cursor](cursor.md).
